Must-fix before production (GO once these are applied)

Run production build, not dev server
Today: shelfeye.service → pi-startup.sh ends with npm run dev (dev/HMR via tsx).
Risk: higher memory footprint and instability over weeks; dev deps kept in memory; Vite overlay hooks.
Fix: build then start compiled server.
pi-startup.sh (replace the final run block)

-# Run the application
-exec npm run dev 2>&1 | tee -a "$LOG_FILE"
+# Build for production and run compiled server
+log "Building production assets..."
+run_with_timeout 900 npm run build || { log "❌ FATAL: build failed"; exit 1; }
+record_phase "build"
+
+# Important: use production server (dist/index.js)
+exec npm start 2>&1 | tee -a "$LOG_FILE"
Never give up on DB reconnection
Today: server/db.ts stops after 10 attempts; if Neon is flaky for >~1 minute, the app may stay down until a restart.
Fix: use indefinite retries with capped backoff.
server/db.ts

-  private readonly MAX_RECONNECT_ATTEMPTS = 10;
-  private readonly RECONNECT_DELAY_MS = 5000; // 5 seconds
+  private readonly MAX_RECONNECT_ATTEMPTS = Infinity; // never give up
+  private readonly RECONNECT_DELAY_MS = 5000; // initial backoff
+  private readonly MAX_RECONNECT_DELAY_MS = 300000; // cap at 5 minutes
@@
-    await new Promise(resolve => setTimeout(resolve, this.RECONNECT_DELAY_MS));
+    const delay = Math.min(this.RECONNECT_DELAY_MS * Math.max(1, this.reconnectAttempts), this.MAX_RECONNECT_DELAY_MS);
+    await new Promise(resolve => setTimeout(resolve, delay));
