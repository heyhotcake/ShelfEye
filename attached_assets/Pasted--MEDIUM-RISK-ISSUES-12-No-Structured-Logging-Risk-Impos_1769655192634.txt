🟡 MEDIUM-RISK ISSUES
12. No Structured Logging
Risk: Impossible to trace errors across microservices (Node + Python)
Impact: Debugging in production takes hours instead of minutes
Fix: Use Winston with correlation IDs:

// server/logger.ts
import winston from 'winston';

export const logger = winston.createLogger({
  format: winston.format.combine(
    winston.format.timestamp(),
    winston.format.json()
  ),
  transports: [
    new winston.transports.File({ filename: 'logs/shelfeye.log' }),
  ],
});

// Middleware: Add correlation ID to all requests
app.use((req, res, next) => {
  req.correlationId = crypto.randomUUID();
  res.setHeader('X-Correlation-ID', req.correlationId);
  logger.info('Request', { correlationId: req.correlationId, method: req.method, path: req.path });
  next();
});

15. Insufficient Input Validation
Risk: Malformed camera configs cause crashes
Impact: Server exits, systemd restarts, brief downtime
Issue: Some routes use .parse() (throws), others don't validate at all
Fix: Use .safeParse() everywhere:

// server/routes.ts
app.post('/api/cameras', async (req, res) => {
  const result = insertCameraSchema.safeParse(req.body);
  if (!result.success) {
    return res.status(400).json({ 
      error: 'Invalid camera data', 
      details: result.error.flatten() 
    });
  }
  
  const camera = await storage.createCamera(result.data);
  res.json(camera);
});

20. Improve Memory Leak Detection
Current: Hourly memory logging
Improvement: Alert if heap grows >10% per hour

let lastHeapUsed = 0;

setInterval(() => {
  const currentHeap = process.memoryUsage().heapUsed;
  const growth = (currentHeap - lastHeapUsed) / lastHeapUsed;
  
  if (growth > 0.1) {
    console.warn(`[Memory] Heap grew ${(growth * 100).toFixed(1)}% in 1 hour - possible leak`);
    // Trigger heap snapshot
  }
  
  lastHeapUsed = currentHeap;
}, 3600000);

21. Replit Autoscale Limitations
Risk: Multiple instances compete for camera access
Impact: Capture runs fail with "device busy" errors
Mitigation: Ensure only ONE instance runs scheduled captures (use distributed lock in DB)
Fix:

// server/scheduler.ts
async executeCapture() {
  const lockAcquired = await storage.acquireDistributedLock('global_capture', 600); // 10 min TTL
  if (!lockAcquired) {
    console.log('[Scheduler] Another instance is capturing - skipping');
    return { status: 'skipped', reason: 'Another instance running' };
  }
  
  try {
    // ... existing capture logic
  } finally {
    await storage.releaseDistributedLock('global_capture');
  }
}
