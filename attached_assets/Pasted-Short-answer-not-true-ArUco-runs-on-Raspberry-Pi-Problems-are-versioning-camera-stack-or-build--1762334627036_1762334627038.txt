Short answer: not true. ArUco runs on Raspberry Pi. Problems are versioning, camera stack, or build choices, not a “fundamental” Pi defect.

What I can verify:

Many users run ArUco on Pi 3/4 at usable rates. Example: Pi 4 reports ~9 FPS at 1080p and higher at 640×480; 20 Hz at 640×480 on Pi-class hardware has been reported in the literature.

Root causes I see in Pi complaints

Wrong package: opencv-python instead of opencv-contrib-python. Result: cv2.aruco missing.

Marker generation/printing: no white quiet zone, low DPI, glossy paper, motion blur.

Dictionary mismatch: e.g., reading DICT_4X4_100 with markers printed from DICT_4X4_50 yields wrong IDs like “7 vs 17.” This is configuration, not hardware.

Expectations on frame size: asking 1080p on Pi 4 drops FPS; downscale to 640×480 if you need speed.

Smoke test (uses Picamera2, ArUco 4×4/100):

from picamera2 import Picamera2
import cv2 as cv

picam2 = Picamera2()
picam2.configure(picam2.create_preview_configuration(main={"size": (640,480)}))
picam2.start()

dict = cv.aruco.getPredefinedDictionary(cv.aruco.DICT_4X4_100)
params = cv.aruco.DetectorParameters()
detector = cv.aruco.ArucoDetector(dict, params)

frame = picam2.capture_array()
gray = cv.cvtColor(frame, cv.COLOR_BGR2GRAY)
corners, ids, _ = detector.detectMarkers(gray)
print(ids)


If this crashes on Pi 5 with OpenCV 4.6, upgrade OpenCV. That crash is a known issue.
